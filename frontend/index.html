Permutation importance on the held-out test set: how much the Random Forest's R² drops when a single feature's values are randomly shuffled. A bigger drop means the model relies on that feature more for out-of-sample prediction.

How the model predicts

  1. Random Forest. The deployed model averages 300 decision trees (max_depth=10), each trained on a bootstrap sample of the training data. Every tree repeatedly splits the 8 input features to isolate groups of days with similar irrigation demand; the forest's prediction is the mean of all 300 trees' leaf values.
  2. Per-tree path decomposition. For a single prediction, each tree starts at its root — whose value is the average demand across all training days — and walks down through a sequence of yes/no splits (e.g. “previous_irrigation_mm ≤ 4.2?”) until it reaches a leaf. At every split, the node's average value shifts up or down; that shift is credited to whichever feature caused the split.
  3. Averaging across the forest. Summing those shifts along the path gives leaf value = root value + ∑ feature contributions, exactly, for one tree. Averaging the root values and the per-feature shifts over all 300 trees gives the breakdown shown on the Predict tab: a baseline plus a contribution per input feature that adds up to the final prediction.
  4. Why this matters. Global feature importance (Training tab) says which features matter on average across the dataset. The per-prediction breakdown says which features mattered for this specific day — e.g. heavy recent rainfall can dominate the decision even for a crop stage that is normally water-hungry.
